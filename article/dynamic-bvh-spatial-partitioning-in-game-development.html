Dynamic BVH Spatial Partitioning in Game Development

Bounding Volume Hierarchies (BVHs) are essential data structures for broad-phase collision detection, ray tracing, and visibility culling in modern game engines. This article explores the core techniques developers use to achieve smooth, high-performance spatial partitioning with BVHs in complex environments. By utilizing loose bounding volumes, incremental tree rotations, dynamic refitting, and asynchronous multithreading, developers can eliminate frame rate hitches caused by frequent structural rebuilds while maintaining optimal query efficiency for thousands of moving entities.

Loose Bounding Boxes and Margin Padding

Constantly reinserting moving objects into a BVH causes significant computational overhead and frame-time spikes. To solve this, engines use "loose" bounding volumes or bounding box margins. Instead of fitting the bounding volume tightly around an object's current mesh, the bounding box is expanded by a velocity-based or fixed margin. As long as the object moves within this expanded margin, the hierarchy structure remains unchanged. The node is only updated or moved within the tree when the entity crosses its margin threshold, drastically reducing tree updates per frame.

Bottom-Up Refitting

For deforming meshes (such as animated characters) or objects with minor positional changes, modifying the tree structure is unnecessary. Dynamic refitting adjusts the bounds of existing nodes from the leaf level up to the root without changing the parent-child relationships. Because refitting traverses the tree in a single bottom-up pass without memory allocations or node re-parenting, it operates in linear time \(O(N)\) and is exceptionally fast on modern CPU and GPU architectures.

Incremental Tree Rotations and Surface Area Heuristic (SAH)

Over time, continuous movement and refitting degrade the quality of the BVH, leading to overlapping nodes and slower spatial queries. Instead of stopping the game to execute a full tree rebuild, developers apply incremental tree rotations. Inspired by AVL and red-black tree balancing, small local subtrees are swapped and evaluated using the Surface Area Heuristic (SAH). By running a fixed budget of rotations per frame, the tree continuously self-heals and retains near-optimal query performance without introducing stutter.

Dual-Tree Architectures (Static vs. Dynamic)

Complex scenes often contain a mixture of static geometry (terrain, buildings) and dynamic entities (players, projectiles, physics props). Partitioning everything into a single BVH creates unnecessary maintenance work. Modern engines split the spatial partitioning into two or more distinct hierarchies:

  • Static BVH: Built offline or on level load using high-quality top-down builders. This tree remains immutable and highly optimized for raycasts and static collision.
  • Dynamic BVH: Built for fast updates and refitting at runtime. Queries simply test against both trees and merge the results, keeping dynamic update costs strictly proportional to the number of moving objects.

Multithreaded and Asynchronous Updates

To ensure spatial updates do not bottleneck the main game loop, BVH maintenance is delegated to worker threads via job systems. Common strategies include:

  • Double Buffering: The physics and rendering engines read from a stable BVH while a background thread computes updates or structural rebuilds for the next frame.
  • Parallel Traversal and Construction: Primitive sorting, bounding box merges, and refitting stages are divided into independent chunks across CPU cores, ensuring smooth performance even in physics-heavy scenarios.
