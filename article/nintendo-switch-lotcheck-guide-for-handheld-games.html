Nintendo Switch Lotcheck Guide for Handheld Games

Passing Nintendo’s Lotcheck certification is an essential milestone for releasing any title on the Nintendo Switch family of systems, requiring strict adherence to technical and operational requirements. In handheld and tabletop configurations, Nintendo imposes a distinct set of compliance criteria designed to guarantee consistent performance, user interface legibility, proper power efficiency, and seamless controller behavior. This guide details the primary compliance guidelines developers must meet to pass Lotcheck specifically for handheld game deployment.

Display and Text Legibility Standards

Games running in handheld mode must account for the built-in 720p screen, which significantly reduces the physical viewing area compared to a television display.

  • Minimum Font Sizes: Text must remain legible at arm’s length. Nintendo recommends minimum font heights (typically 24 pixels on a 1080p canvas, scaled to 16 pixels on 720p) for critical information, including dialogue, tutorials, and system messages.
  • Safe Areas and Aspect Ratios: All critical user interface (UI) elements must fit cleanly within the screen boundaries without cropping, distortion, or overlapping system indicators like the battery or network status icons.
  • Touch-Screen Scaling: If touch input is supported, interactive touch targets must meet minimum physical touch area standards (generally at least 9mm by 9mm) to prevent misclicks.

Docking and Undocking Transitions

Handheld compliance requires the game engine to adapt dynamically to hardware state changes without crashing, freezing, or dropping assets.

  • Resolution Switching: When a user transitions between docked mode (up to 1080p) and handheld mode (720p), the application must reallocate rendering buffers instantly without breaking the aspect ratio or causing visual artifacts.
  • Performance Clock Adjustments: The Switch lowers its GPU and memory clock frequencies when undocked to manage thermals and battery life. Developers must ensure the game maintains its target framerate despite this drop in raw computing power, often by leveraging dynamic resolution scaling.

Controller Configuration and Input Handling

Nintendo requires titles to gracefully handle all possible controller arrangements and transitions native to portable play.

  • Attached Joy-Con Support: Handheld mode strictly relies on Joy-Con controllers physically attached to the console rail. The game must seamlessly recognize when controllers slide into the rails, switching the input mode from wireless to the direct handheld configuration.
  • Tabletop Mode Flexibility: In tabletop mode, Joy-Con controllers are detached while the console rests on a flat surface. Titles must support standard single-player or shared horizontal Joy-Con configurations, displaying accurate button glyphs that reflect the physical orientation of the detached controllers.
  • Controller Applet Invocation: If an input state becomes invalid (such as a detached Joy-Con running out of battery during tabletop play), the game must automatically invoke the native Nintendo Controller Applet rather than leaving the player stuck on an unresponsive screen.

System Interruptions and Sleep Mode Management

Handheld devices are regularly suspended, locked, or interrupted by native platform overlays.

  • Sleep Mode Recovery: Pressing the physical power button places the console into sleep mode. The application must suspend all active threads, audio output, and rendering immediately. Upon waking, the game must resume state without audio desynchronization, asset loss, or crashes.
  • Home Menu Interrupts: Pressing the Home button must trigger an automatic pause in single-player experiences. The title must mute all game audio and hold its execution state cleanly in the background.
  • Software Keyboard Integration: Any in-game text field must trigger the native Nintendo Switch Software Keyboard applet. Developers cannot force users to rely solely on external or custom inputs without providing full native applet compliance.

Battery Conservation and Thermal Compliance

Hardware limitations in handheld mode mandate strict limits on power consumption and heat generation.

  • Background Throttling: When the game is idle or minimized via the Home menu, processing load must drop to prevent rapid battery drainage.
  • Continuous Heavy Load Restrictions: Games that run the hardware at sustained maximum operational thresholds risking thermal throttling will be flagged during Lotcheck. Profiling tools must be used to keep CPU/GPU utilization within permissible handheld power envelopes.

Network Reconnection and Error Handling

Portable play frequently results in dropped connections as players move between Wi-Fi networks.

  • Graceful Disconnection: If a Wi-Fi connection drops, the game must not hang or crash. It must display a clear, non-blocking error message informing the player of the network loss and provide an offline path or a prompt to reconnect.
  • Airplane Mode Compliance: The application must correctly identify when Airplane Mode is active and suppress continuous background network requests that lead to endless loading states or system lockups.
